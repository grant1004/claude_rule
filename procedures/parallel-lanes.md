# 一次處理多個問題（平行車道）

我一次給了多個問題，或說「平行處理」時用。做法是先分診、分組，再照 `dispatch.md` 派出、驗收、落地；和平常的差別只在一開始就把互不相依的問題同時派出去。一條車道就是一個任務，車道卡就是派工單。

## 啟動與中途加入

- 一般啟動：我說「平行處理」並列出問題。建置和測試的指令從專案的 CLAUDE.md 找，找不到再問。
- 自動連續做：我用 `/goal` 啟動，條件以 `WIP.md` 為準。範本：
  `/goal 照平行車道流程處理下列問題和之後加進 WIP.md 的問題，直到 WIP.md 裡每個問題都是「已落地且全套測試通過」「受阻」或「略過」，而且最後一次回報列出了 WIP.md 的完整內容和最後一次全套測試的輸出。不可以刪除或放寬測試，不可以 push，不可以動落地分支以外的既有分支。最多 60 回合。問題：1. <問題一> 2. <問題二>`
- 執行中我又給新問題：照核心規則第 1 節處理，和進行中的車道比對之後派出或排隊。

## 分診與分組

1. 分診：把我給的問題整理成問題地圖，列出每題的疑似根因、會改到的檔案、彼此的關係。同根因的合併成一題。這一步只讀不改；要讀的檔案多就派探索代理。
2. 分組：按會改到的檔案分車道。檔案重疊或屬於同一個模組的問題放進同一條車道，在車道內依序處理。會動到共用介面或資料格式的變更排在最前面，單獨落地之後再開其他車道。
3. 查行為相依：某條車道要改的檔案，被另一條車道的檔案呼叫或引用時，在兩張車道卡上互相註明，並讓其中一條先落地再開另一條。檔案不重疊不代表行為不互相影響。
4. 每條車道寫一張車道卡，格式同 `dispatch.md` 的派工單，多寫兩項：負責哪幾個問題、依賴哪條車道先落地。
5. 把問題地圖和車道卡寫進 `WIP.md` 並列給我看。我開工時說過要先確認，就等我確認；沒說就直接派出。標成「略過」的問題不派。

## 派出與落地

- 互不相依的車道同時派出，全部用 `cr-worker-isolated`，把工作目錄留給合併用。專案不能用 worktree 時，改用 `cr-worker` 一條一條做。
- 車道之間不互相聯絡，一律經過主對話。
- 驗收、合併、清理照 `dispatch.md` 的「完成通知進來時」。一次只合併一條。每合併一條，其他還沒落地的車道在回報前都要 rebase 並重驗，這一步已經寫在它們的執行規則裡。
- 全部結束時照 `dispatch.md` 的「收尾」回報，另外附上 `WIP.md` 的完整內容和最後一次全套測試的輸出。

## 模式二：每條車道由我開一個獨立 session

我指定要用獨立 session 時才用，例如某條車道需要我在場操作。

1. 主對話用 `git worktree add ..\<專案>-<任務代號> -b cr/<任務代號>` 幫每條車道建 worktree，並替每條車道寫好一段開場訊息給我。第一行是「你是平行車道的執行者，不是調度者。先讀 `~/.claude/claude_rule/agents/cr-worker-isolated.md`，照裡面的執行規則、交付和回報格式做；你已經在自己的 worktree 和分支上，不必再開分支。」，後面接整張車道卡。由我在各個 worktree 開 session 貼上。
2. session 之間只傳三種訊息：「就緒」「已落地」「需要動到車道外的檔案」。訊息發不出去，就把內容給我，由我轉達。
3. 車道先 commit 再發訊息。主對話沒收到「就緒」時，用 `git log <落地分支>..cr/<任務代號>` 查看進度，不要只等訊息。
4. 主對話收到「就緒」後照 `dispatch.md` 驗收，合併前先問我；合併後向其他車道發「已落地」，收到的車道 rebase 並重驗。
