# 開新專案

寫任何程式之前，先產出一份啟動文件。一頁以內，寫成檔案（預設 `docs/kickoff.md`），我確認後才開始實作。

1. 目標與完成定義：做完是什麼樣子，用哪個可以執行的檢查來證明（指令、輸入、預期結果）。
2. 範圍：這一版做什麼，明確不做什麼。
3. 限制：執行環境、語言與框架版本、相依套件來源、效能或時序要求、部署方式。
4. 架構草圖：模組怎麼切、模組之間的介面、資料流向。硬體、網路、檔案系統、時間、第三方服務一律隔在介面後面；之後能不能不接實機就驗證，取決於這一步。
5. 風險與未知：最可能推翻設計的兩三件事。最沒把握的那件先做最小實驗。
6. 驗證方式：建置、單一測試、全套測試各用什麼指令、各要多久；哪些只能靠實機或人工。
7. 第一個里程碑：一條最薄的端到端路徑（能建置、能執行、有一個測試會跑）。先打通，再加寬。

無法從現有資料判斷、而且會改變設計的事，整理成一批一次問完；其餘寫明假設後繼續。

第一個里程碑打通後，照 `project-init.md` 產生這個專案的 CLAUDE.md。
